On a table an add-on's ledger writes, an app's role that may add rows is never given a column the ledger keeps: one its code sets on the rows it changes (a hold's or a design's state), or the link to the receipt of a posting's row (`receipt_id`), which would pass a role's row off as a posting's. The add-on's `appGrants.creatable` naming one is refused, and a grant is cut to fit whatever the add-on lists. The columns a posting fills on the rows the ledger adds (a proof version's words) may still be given to a row the role adds, and `appGrants.writable` may no longer name `receipt_id` either.
