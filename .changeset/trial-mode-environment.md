An operator who runs Adminium for other people can now describe a trial or a paid installation in the environment. `ADMINIUM_TRIAL_MODE=on` and `ADMINIUM_HOSTED_MODE=on`, with `ADMINIUM_TRIAL_ENDS_AT`, `ADMINIUM_PUBLIC_ORIGIN`, the trial caps, the Upgrade address, the mail relay, `ADMINIUM_OPERATOR_DOMAINS`, the operator token, listener and events address, operator AI and the Designer's start prompt are all checked when the server starts. A trial refuses to start without an end date, a setup token, its public address and a database host list, and either profile refuses a value that contradicts it (`ADMINIUM_NETWORK_POLICY=open`, `ADMINIUM_LOCAL_DATABASES=setting`, `ADMINIUM_RATE_LIMIT_SCALE`, `ADMINIUM_ADD_ON_DEV_TRUST`, `NODE_OPTIONS`, the bridge, a seeded storage destination, and in a trial telemetry or a map server) or a value holding a control character. What a profile implies is enforced whatever the variable holds, a project's `.env` is not read at all and its config cannot set any of these. The operator token and the relay are held out of the process environment, and can be given as files. `/system/info` now says whether a trial runs, until when, how many days are left and where Upgrade goes, signed out too. Settings the operator decides are shown read-only with "Set by the operator" and a change to them is refused: for now the two outbound-call consents (locked off in a trial, on the first-run screen too) and "Allow databases on this server". `GET /api/v1/readyz?deep=1` also waits until the installed add-ons are loaded. The behaviour of each switch follows in later releases; without either profile nothing changes.
