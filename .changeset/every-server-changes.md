'@adminium/server': patch
---

What changes on every server, trial mode or not. At boot the meta store's address (`ADMINIUM_META_URL`, or the one a move wrote to `adminium.json`) is looked up, and a host that is or resolves to a cloud metadata address stops the boot with the host it named; a name that does not resolve yet is still left to the driver, so a database container that starts a moment later is no refused boot. The boot also stops on a control character in any trial, hosted, operator, operator AI or start prompt variable, and on an `ADMINIUM_TRIAL_*` variable set without `ADMINIUM_TRIAL_MODE=on`, naming it. Setting `ADMINIUM_PUBLIC_ORIGIN` or `ADMINIUM_OPERATOR_DOMAINS` now changes an ordinary server too: it answers 421 on any other host name (only `/api/v1/healthz` and `/api/v1/readyz` answer on every name), the address in email links becomes that origin and can no longer be changed in Studio or learnt from a browser, and only the listed domains can be mapped to an app's side or the add-on pages; make sure your proxy passes the host name visitors asked for before you set either. Every route now says whether it is for the instance's own people or the public, and a route that says neither counts as public: that changes nothing until the operator endpoint hides the public pages, when all of them answer 404. `/system/info` carries `trial` and `offByOperator` on every server (all off or allowed outside the two profiles), the email settings reply carries `locks`, and refusals use two new codes, 403 `OFF_BY_OPERATOR` and 409 `SET_BY_OPERATOR`. `GET /api/v1/readyz?deep=1` is new; plain `readyz` answers as before.

Two changes reach every install, not only a trial or hosted one. An app's screens (its side builds) are now always compiled with the engine's own TypeScript settings: a `tsconfig.json` or `jsconfig.json` in the app or the project is no longer read, so a `paths` alias such as `@/components/*` or a `baseUrl` set there no longer resolves, and a screen that imports through one fails to build. Import the app's own files by a relative path (`./components/Card`) or an installed package by its name. And free SQL text that reaches a schema change without being typed in the schema editor, an expression default, a check or a column type carried from the database or a schema import, is refused with 422 `VALIDATION_FAILED` (`details.reason: UNSAFE_SQL_TEXT`) when it could end its clause, start a second statement or hide the rest of one: a `;`, a comment, a backslash, a dollar sign, or a quote or parenthesis left open. An expression default now goes in as `DEFAULT (…)`. The schema editor says in words which kind of text was refused.
