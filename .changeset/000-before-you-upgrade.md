**Before you upgrade to this release, read these four points.** (1) **Old notifications are deleted for good.** The first cleanup after the upgrade, at 03:00 UTC, deletes notifications read more than `retention.notificationsDays` ago (90 days unless you changed it). Unread ones stay until they are read. To keep older ones, raise that setting first: it has no screen yet, so the statement for your meta store is in [Keep read notifications longer](https://docs.adminium.dev/self-hosting/upgrades/#keep-read-notifications-longer). (2) **API keys made by suspended people stop working.** The upgrade revokes, once, every API key made by someone who is suspended at that moment, and writes each one to the audit log with who made it. A revoked key cannot be restored, even by reactivating the person, so a shared integration running on one needs a new key. A key with no recorded maker keeps working: revoke any you do not recognise on the API keys page. (3) **A key or role holds at most what the person handing it out holds.** A new API key can never hold more than whoever makes it, and only a signed-in Super Admin can make a Super Admin key. Someone who manages roles and is not a Super Admin can give out only what they hold, and cannot edit roles above them. Keys and roles that exist today are not changed, so if a custom role has held "Manage API keys" or "Manage roles", review your keys and who holds which role. (4) **If you run several replicas,** finish replacing all of them before you suspend anyone.
