The desktop app opens an "Export everything" file: File → Open a project… picks the file, and Start makes a NEW project from it (an open project is closed first; nothing goes into it). The engine reads and checks the file first (`adminium import-zip --dry-run --json`), the person names the project and its folder, picks the Super Admin who signs in first and types their new password twice; the import runs through the same `import-zip` with the export's rules, the password on standard input. A whole-server archive is refused with the command that restores one (`adminium archive restore`), and a changed or unsafe file is refused with nothing made. A connection that came without its connection string now shows as Draft in Studio, as a new one without a string does. `adminium import-zip --json` prints the outcome or the refusal as one line of JSON. Studio's Export everything page says "Choose Open a project and pick the file." for the desktop app again. An export no longer carries who a desktop app signs in without a password (`designer.ownerId`, `designer.localOwnerId`), and a restore with the export's rules drops them from any file; `import-zip --local-owner` makes the Super Admin given the password this computer's owner instead (the desktop app passes it). A project folder that came in an export gets the `.env` its config reads, written as `new` writes one: each project database's variable pointed at the restored SQLite file, or empty when its string must be entered again, and the names `.env.example` lists, empty.
