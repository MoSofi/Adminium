An app's email is no longer sent with a `{{…}}` placeholder in it. A template that named a value nothing fills (a secret column, a personal column of a linked row, a link the message does not have, a misspelt name) went out with the placeholder printed as written, so a client could get "Open the handover: …#{{project.share_token}}". Such a message is now marked failed, and its error names the variable, for example "Not sent: nothing fills {{project.share_token}}". The template checked is the one sent, and `recipient.name` and `recipient.first_name` are always filled, empty when the client has no name on file, so a greeting never stops a message. A code (a handover link's) goes only to the person it belongs to: to the address their own row keeps, from a row that is theirs or links to them. A message a desk addressed by hand to another address, or one linking one client and another client's project, is failed with a sentence saying so, and a desk may link a message only to rows it can read. Adminium's own emails and test sends are unchanged.
