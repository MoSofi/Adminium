An app's email is no longer sent with a `{{…}}` placeholder in it. A template that named a value nothing fills (a secret column, a personal column of a linked row, a link the message does not have, a misspelt name) went out with the placeholder printed as written, so a client could get "Open the handover: …#{{project.share_token}}". Such a message is now marked failed, and its error names the variable, for example "Not sent: nothing fills {{project.share_token}}". The template checked is the one sent, and `recipient.name` and `recipient.first_name` are always filled, empty when the client has no name on file, so a greeting never stops a message. The code a shared link opens a row with (a handover link's) goes only to the person it belongs to: to the address their own row keeps, from a row that is theirs or links to them by the link that names them (a project's client, never the client who referred them). A message a desk addressed by hand to another address, or one linking one client and another client's project, is failed with a sentence saying so. Any other code, such as a booking's reference, is printed wherever the message goes: a receipt sent to an address the desk typed, or to someone with no email on file, carries its reference. A desk may link a message only to rows it can read, and so may the person whose import makes one; so, too, whoever queues a held or failed message to go. Adminium's own emails and test sends are unchanged.
