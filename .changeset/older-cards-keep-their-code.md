An add-on's ledger can bring a row in under a code it already has: a code rule that says `givenByLedger: true` lets the add-on's own answer give the code on a row it adds (an older gift card, moved in under the code its holder has always had). The code is kept when it is the rule's prefix and 4 to 16 capital letters and digits and no other row has it; with none given Adminium makes one as before; a change never writes a code, and no person's save gains anything. A row such an answer adds may also start in a state that only a planned move reaches from the first state. On a server with few tables a price rule's "make them for me" was refused because a link Adminium had only guessed from a column's name counted as a real one; it no longer does. A price rule that cannot be stored is now refused before any column or table is made for it, in the review and in the save; it used to add them first.
