An app whose payable sits in a part it installs without (a part built on an add-on the app only suggests) now installs: the payable goes with the part, whole, when any table it names is not made or a link column it names went with the part, and with it a public entry's pay link on that table and, when no payable is left, the app's refund right. Before, the manifest check refused such an app ("is not a table of this app"). When the add-on is connected later, the payable comes with the part, switched off.
