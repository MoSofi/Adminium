'@adminium/server': patch
---

Storage destinations are now checked on every way in. A `local` destination ("Another folder on this server", or `ADMINIUM_STORAGE_URL=file:///…`) can no longer use Adminium's own folders: the data directory, its `backups/`, `files/`, `tmp/`, `add-ons/` and `pre-restore-…` folders, the meta store's file, or any folder that holds the data directory, `/` included. The folder's real path is checked, so a symlink into one of them is refused too. The new `ADMINIUM_STORAGE_DIRS` variable lets a server's operator name the only folders allowed; unset, any other folder works as before. S3 and WebDAV endpoints are now looked up when they are saved or tested, and before a file's requests (again at least once a minute while connections to them stay open, and after a request that failed); each address is checked (cloud metadata always refused, this machine refused in production, the server's own network refused under `ADMINIUM_NETWORK_POLICY=strict`), and the request goes to an address that was checked, with the host name kept for TLS. Connections to a checked address are kept open between requests, so a page of thumbnails no longer opens one per picture. An `ADMINIUM_STORAGE_URL` that names a refused folder or endpoint now stops `adminium start` with the reason, and so does one whose host cannot be looked up while no storage destination exists yet, instead of quietly writing every file to the server's own disk. A destination saved earlier that breaks one of these rules stops working until it is changed. The desktop app ignores `ADMINIUM_STORAGE_DIRS`.
