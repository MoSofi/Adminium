'@adminium/server': patch
---

A production server now looks a source database's host name up before it opens each connection pool, and checks every address the name gives. A name that points at the server itself is refused unless it is in `ADMINIUM_DATABASE_HOSTS`, a name that points at a cloud metadata address is always refused, and a name that does not resolve is refused, where before it was left for the driver to try. The database driver then connects only to the addresses that were checked, so a name whose answer changes a moment later cannot send the connection somewhere else; the name is still used for TLS, so certificate checks and providers that route by it (Neon) work as before. More cloud metadata addresses are recognised (Alibaba Cloud's and Oracle Cloud's), as are addresses written inside IPv6 ones (NAT64, 6to4 and the old IPv4-compatible form). The drivers are now given the connection string's parts instead of the string itself, so a query parameter can never change where they connect. One visible change from that: in a PostgreSQL connection string, `ssl=false` (or `ssl=0`) now really switches TLS off, where the driver used to read the word `false` as on; a connection that only worked because of that mistake needs `sslmode=require` instead. Outside production mode (the desktop app, Adminium run with `npx` on your own computer) nothing is looked up and connections work as before.
