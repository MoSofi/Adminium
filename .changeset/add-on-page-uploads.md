An add-on's own page puts a file into a file column of one of its own rows: `useUpload(table, column)` in the data kit uploads the bytes through the files route, judged by the column's rule as a record form's upload is, then saves the row with the file, which is when the file becomes the row's; a file whose save is refused is thrown away at once. The upload's reply for an SVG says what the cleaner took out of it (`removed`: `<script>`, `onload`, `inkscape:*` for all of an editor's notes), so a page can say "We removed …". An add-on page reads the price an app keeps for one of its rows on the app's own table that links to it, with the reader's own grant: documented in the add-on guide.
